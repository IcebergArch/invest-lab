# A 股政策事件研究：固定窗口与证据契约

`quant_lab.event_study` 把央行政策等事件作为**事先登记的解释变量**，观察股票、宽基指数、成交量和成交额在固定交易日窗口的变化。它不从价格曲线反推事件，也不把事件窗口挑到收益最好为止。当前输出是研究报告和可重放记录，不能解释成已经验证的交易策略或政策因果效应。

## 事件登记

事件登记为 JSON 数组，每条至少填写：稳定 `event_id`、标题、政策类别、公告日期/时间、时间精度、生效日期、官方原文 URL、来源性质和历史可见时点的把握程度。政策幅度必须带原文单位；定性公告可明确设为 `null`。同一场发布会的其他措施写入 `co_announcements`，报告会提示不可单独归因。

```json
[
  {
    "event_id": "synthetic.rrr.example",
    "title": "合成降准公告（仅示意格式）",
    "category": "monetary_policy.rrr",
    "announcement_at": "2024-01-25",
    "time_precision": "date",
    "effective_date": "2024-02-05",
    "source_url": "https://example.org/official-notice",
    "publication_certainty": "official_verified",
    "availability_confidence": "date_verified",
    "magnitude": -0.5,
    "magnitude_unit": "percentage_point",
    "co_announcements": ["同期其他政策（如存在，应按原公告填写）"]
  }
]
```

上面的域名和日期只用于说明接口，不能当作真实事件输入。真实登记需逐条核对公告原文和历史发布时点；迁移后的网页显示“发布时间”不自动证明当年同一时刻市场已能看到。`availability_confidence` 的判定直接决定事件是否可用于固定窗口：

| 值 | 含义与计算规则 |
| --- | --- |
| `clock_verified` | 公告的分钟可核实。仅在交易日 09:30 前发布时，当日可作为首个完整日线反应日；盘中或盘后发布，从下一交易日开始。 |
| `date_verified` | 日期可核实，具体分钟或历史可见性不能核实；即使网页展示钟点，也统一从下一交易日开始。 |
| `unverified` | 历史可见日期不能确认；不计算反应窗口。 |

`time_precision=date` 不能同时声明 `clock_verified`。`publication_certainty=unverified` 也不会计算反应窗口。登记日超过 `data_asof` 的事件保留为 `not_available_asof`，没有未来收益。生效日单独保存，**反应窗口按公告可见时间**定位，因为市场可以在措施正式生效前定价。

## 行情输入

`evaluate_event_study(events, bars, benchmark_id=..., asof=..., cohorts=...)` 接受 `CanonicalDailyBar` 或显式构造的 `EventDailyBar`。股票须为同一种复权口径：`forward_adjusted` 或独立标明的 `qlib_adjusted`；同一次实验不得混用两种股票口径。宽基指数保持 `index_points`。只计算各标的内部无量纲收益率，再做“股票收益率 − 同期指数收益率”，不会把复权股价与指数点位直接比较。

`CanonicalDailyBar` 可直接由 `MarketStoreAdapter` 的只读流取得。若主库同日同时有原价和前复权价，调用方须明确筛出前复权股票行；引擎会拒绝同一标的同日重复行和混合口径。`EventDailyBar` 为 Qlib 等独立归档预留适配入口；对尚未确认单位的 Qlib `volume`、`amount`，必须传 `None`，不得写成“股”或“人民币”。来源标识、数据集标识、源哈希和观察时间参与输入指纹。

```python
from datetime import date
from quant_lab.canonical_data import MarketStoreAdapter
from quant_lab.event_study import (
    evaluate_event_study, load_event_registry, append_event_study_record,
)

stock_ids = ["stock:000338.SZ", "stock:002475.SZ"]  # 示例：事先冻结选择
index_id = "index:000300.SH"
asof = date(2026, 9, 29)
bars = (
    bar for bar in MarketStoreAdapter("data/quant/market.sqlite3").iter_bars(
        instrument_ids=stock_ids + [index_id], end=asof,
    )
    if bar.asset_type == "index" or bar.price_basis == "forward_adjusted"
)
result = evaluate_event_study(
    load_event_registry("data/quant/reviewed-policy-events.json"),
    bars, benchmark_id=index_id, asof=asof,
    cohorts={"frozen_example_cohort": stock_ids},
)
saved = append_event_study_record("reports/event-studies", result)
print(saved["report_path"])
```

示例路径需要存在且事件文件需先经人工核对；函数不会抓取或猜测政策事件。分组成员也应在看事件收益前确定，历史行业归属需要带有效日与发布日期的数据，否则只能标记为事后研究分组。

## 固定计算口径

宽基指数已存交易日构成日线日历。`0` 是公告后首个完整可交易日；若公告时间只有日期，保守使用次一交易日。窗口均按**交易日**数，而非自然日：

| 窗口 | 区间收益起止 | 用途 |
| --- | --- | --- |
| `pre_20` | `-20` 到 `-1` | 公告前市场变化 |
| `pre_5` | `-5` 到 `-1` | 临近公告的变化 |
| `post_0` | `0` | 首个完整交易日变化 |
| `post_1` | `0` 到 `+1` | 首日及次日累计变化 |
| `post_5` | `0` 到 `+5` | 短期累计变化 |
| `post_20` | `0` 到 `+20` | 约一个月累计变化 |

每个窗口收益都用“窗口末日收盘价 ÷ 窗口首日前一交易日收盘价 − 1”。对照为同一交易日的宽基指数收益；`excess_return` 是两者之差，是描述性市场调整值，不是已识别因果的“异常收益”。在公告日有行情时，还单列该日收盘对前收盘的观察值；盘中或盘后公告尤其不能把这个观察值当作公告后可执行的收益。

成交量比和成交额比分别是窗口内日均股数或人民币金额，除以固定 `-20` 到 `-6` 日的日均值。只在标的自身单位已核实、控制段和目标段数据完整、控制均值大于零且相关日不标为不可交易时计算。指数点位和股票价格水平不比较；不同股票的成交量或金额水平也不混为同一单位的价格因子。没有股数或人民币口径时显示不可用，不用 OHLCV 推算源端未知单位。

窗口内缺一交易日行情即返回 `missing_bar`；窗口尚未走完返回 `insufficient_future_history`；控制段不足或金额/数量不可用有各自状态。已验证停牌/ST 等不适合交易的状态保留在 `tradability`，对应流动性比不算；无历史状态证据显示 `unknown`，不会冒充“可交易”。

## 预测稳定性的事件切片

`tag_event_regime_days(events, trading_days, asof=...)` 另按预先固定的 `-5` 到 `+20` 交易日建立政策应激切片，多个事件窗口取并集，返回逐日事件标签、核心候选交易日数、应激交易日数、从核心评估中排除的日数和事件重叠数。事件研究结果的 `regime_slices` 也保存同一标签。预测/策略评估应分别在核心段和应激段计算误差、风险、收益和覆盖率；应激段保留，不因表现差而从总账删除。

这些计数的分母是**指数交易日历**，并非某模型已完成的预测样本数。上层评估还需按每条预测的目标日重新统计核心/应激样本覆盖和缺失原因。

这里的核心段排除属于**事后诊断**。公告前 `-5` 日是在事后才知道会有该事件，未预告的未来央行措施也不能提前规避。因此这些标签不能直接作为实盘过滤信号。未来若要限制某类可预知日程，须另有带历史发布时间的日历，并在预测起点验证当时确实已知。

上层稳定性评估可据预先冻结的阈值把模型分为三档：广泛场景表现稳定；仅在已验证的市场状态与时间范围内稳定、其他时候弃用；整体粗糙且不稳定、不给可执行预测。分档不能只从几次选中的政策事件或全样本平均误差得出，需要时间外样本、可交易性、费用和黑天鹅压力测试共同支持。个股量价数据无法单独识别某家机构的行为，报告只能称“交易行为特征”，不把聚合成交量解释为特定机构动作。

目前预测误差三档的具体统计门槛、预声明范围验证方式和真实档案结果见 [预测稳定性分层审计](forecast-stability.md)。事件核心段只作事后诊断；完整配对样本才参与分档。

## 记录与解释边界

实验结果含事件登记、预先固定的窗口和控制段、输入数据 SHA-256、各股票及预登记分组的完整样本数、缺失信息、复权/来源口径。`append_event_study_record` 每次生成新的 `.json` 与 `.md`，不覆盖旧实验；读回时校验两者哈希。报告优先给人读，JSON 供后续批量复盘和策略研究使用。

当前行情采集时间并非历史首次公开时间，复权价和股票池也没有完整的历史版本快照。事件研究能说明“在这些已保存数据上，事件前后价格和量额如何变化”，不能证明当年可提前收到相同数据、在某个开盘价成交或扣费后赚钱。宽基对照也不能排除同期财政、监管、地缘风险、行业消息等共同冲击；同场政策打包发布尤其不能归因给一项措施。单次事件的股票收益高度相关，因此暂不输出把每只股票当独立样本的置信区间。

货币宽松可能抬升风险偏好和估值倍数，但“企业内在价值未变”不是价格曲线可以验证的事实。结果保留 `fundamentals_status=not_collected`；后续需接入带原始披露时间的利润、现金流、资产负债、股本和重大公告，再分别检验现金流预期与折现率变化。

2024-09-24 沪深 300 **公告日**已观察到 +4.33%，但发布会中具体措施的历史可见分钟未核实；固定规则保守地从 **9 月 25 日**计算完整日线反应，所以上表不把 +4.33% 算进“首日”。同场又有利率、房地产与股市支持措施，+5 日变化不能归给单一降准。其他日期也受到同期新闻和整体行情影响。这里是事件扰动下的压力切片，不是“央行放水必然涨”的交易规则。

扩展报告复用预测基准 `forecast_qlib.select_stratified_cohort` 的固定规则：按交易所、首次记录区间年代和该区间在发布日前是否结束分层，每个非空层最多取 3 只并按 SHA-256 固定排序。2026-09-28 发布版本选中 14 层、40 只，其中 19 只的记录区间已结束；结束区间不等于核实退市。选中的 Qlib 有效 CLOSE 共 98,327 条，主库沪深 300 指数点位 1,391 条，合计 99,718 条输入。Qlib 原始归档 SHA-256 为 `73f17f04b8710809f2881e20c3322990b39ecddf376f4b0e6d0c9acd0a6dede5`。这 40 只与已归档预测基准的样本 ID 一致，但作为 2026 年发布版本的**回顾性抽样**，不能代表当年的完整 A 股股票池。

宽基指数使用主库的 `index_points`；Qlib 股票使用独立的 `qlib_adjusted` CLOSE 特征。两者只经各自收盘价比值形成无量纲收益，绝不比较或合并价格水平。Qlib 的成交量/金额原始特征虽存在，但单位未核实，本次两种量比全部留空；指数历史来自当前主库而非同一冻结 Qlib 发布版本。40 股报告的逐股来源文件哈希、有效/缺失日数和分层 ID 都保存在完整 JSON 中，主库指数使用过的同步批次也保留在血缘字段。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 scripts/run-event-study-qlib.py
```
