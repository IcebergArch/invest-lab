# 从研究系统走向封闭式自动交易：阶段门槛

## 用户每天看到什么

系统的首屏应只有三块，不要求用户阅读因子表：

1. **钱在哪些方向更活跃**：先说明全市场成交额的升降，再列最多三个成交占比变化最明显的大类，并明确区分“成交活跃”“融资变化”“可核对的买卖净额”。来源缺失或口径改变时写“暂无可靠数据”。
2. **值得复核的股票**：最多五只，逐只给出为什么入选、预期持有窗口、主要风险、历史同类样本数与收益区间。未经过时间外校准时，预期收益和上涨概率留空，不用规则分数冒充预测。
3. **你决定，我复盘**：记录观察、跳过、实际人工交易及理由；到期回填策略预测、标的走势和真实持仓结果，归因后提出下一版规则。研究建议与真实订单永远分开。

适配个人时间：收盘后形成初筛，次日 10:30 后人工核验并决策。分钟级成交收益在拥有对应分钟数据前不得由日线估算为“实测”。

## 3 / 6 / 12 个月目标

以下是**验收门槛，不是按日期保证上线**。

### 0–3 个月：数据参考与可用筛选

- 覆盖可核对的全 A 股现存与历史标的；报告每日注明覆盖率、缺失率、最新交易日和来源。退市、ST、停牌及财务披露时间可按历史日期查询。
- 候选发布门槛：目标股票池与已完成日线特征计算的股票池逐日对账；默认要求目标池覆盖率不低于 99%，当日数据滞后或关键风险字段缺失的标的不进入推荐。这个阈值是工程质量门槛，不是策略收益保证。
- 一页报告能让用户在 1 分钟内读懂大势、成交关注度和最多五只股票候选；每条候选同时说明被排除的主要风险。
- 信号、特征、参数、代码版本、数据快照与用户回执均有 ID。未来 5/20/60 日结果到期后自动复盘。
- 回测通过手算账本和未来扰动测试；和合适基准、交易成本、可交易性比较。新增策略不修改主流程。

### 3–6 个月：预测与风控证据

- 以严格时间顺序做滚动训练/验证/测试。固定未见过的时间段做最后评估；报告展示各市场环境下样本数、收益分布、最差尾部、成本后结果。
- 每次筛选固定 `policy_version`、候选分数、风险指标和当时股票池；把用户“观察/跳过/行动”与实际成交回执分别记录。复盘先比较信号后 5/20/60 日价格结果，再比较实际交易收益，不把两者混同。候选规则的新版本必须与旧版本在同一时间外区间、同一成本及同一风险预算下比较，胜出后才替换。
- 上涨概率和收益区间经过校准；校准不足时输出“无可靠估计”。记录模型漂移和策略失效触发条件。
- 策略级与组合级风险约束：单标的/行业集中度、流动性、单日与连续亏损、最大回撤、波动异常、停牌/跌停、数据延迟与异常价格。
- 实盘前至少进行逐日影子运行：生成候选与模拟订单，但不发送券商；每次预测、阻止、调整都有理由。

### 6–12 个月：受控自动化准备

- 仅在前述门槛通过后连接券商沙盒，再做小规模、可随时停止的灰度运行；默认人工确认，不以“封闭式”省掉审计与停止机制。
- 独立的风控层在订单发出前校验资金、仓位、价格、流动性、交易时段和交易规则；券商拒单、部分成交、重复回报与断网都有幂等处理。
- 黑天鹅演练覆盖跳空、大面积跌停或停牌、连续流动性枯竭、行情源冲突/中断、财务重述、极端波动、错误时间戳和券商故障。触发时停止新单并给出人可理解的原因。
- 连续影子运行和灰度记录满足事先写定的成功/失败阈值，独立复核后才考虑无人值守模式。黑天鹅风险无法被保证规避，只能限制暴露、检测异常并安全停机。
- 上线前必须由用户给出可承受的最大账户回撤、单笔损失和单日损失上限。未定义这些约束时，系统只能继续研究和影子运行，不能自定风险预算。

## 架构保持简洁

单机 Python + SQLite 起步；数据适配器、不可变快照、特征、策略、回测、预测、候选、回执、风控各有接口。先确保同一信号可复算；没有性能瓶颈前不引入分布式服务。报告是当前产品界面，自动下单是最后一个可替换适配器。
