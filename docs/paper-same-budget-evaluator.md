# Runtime2 账户的同预算前瞻对照

`scripts/paper_same_budget_evaluator.py` 只读取 `quant_paper_pool` runtime2 账户，不写入账户、不补历史交易、不设置定时任务。每次调用先核验配置的策略及运行时代码哈希、逐条 session 的前序哈希、决策哈希与执行链接，并用冻结的撮合函数重放已有策略与原基准账本。原价条、前复权来源、日期、账户和订单字段缺失或不符时直接报错。两类价条的 `fetched_at` 都须不早于该 session 交易日北京时间 15:05，且不能晚于当前真实时间；开户价条还须不晚于 `config.created_at`。session 日期须已到北京时间 16:00，未收盘当日和未来日期直接拒绝。首个已观测代理成交还要求账户 `config.created_at` 及上一 session 的所有原价/信号价条抓取时间早于成交日 15:00；后续成交也要求上一个 session 的所有输入早于当日 15:00。

两个新增对照均使用账户相同的初始资金、股票池、未复权收盘价、100 股整手，以及买卖每侧万分之五；压力结果使用每侧万分之十五。两者都在策略原 session 的相同日期进行代理成交和估值：

| 对照 | 每日目标与交易 |
| --- | --- |
| 固定 80% 等权买入持有 (`shadow`) | 首个未来观测日目标总仓位 80%，同池等权买入，之后只按每日原价估值，不再平衡；尚未卖出时净值只扣已发生的买入费。另列“此刻全卖”的估计卖出费，不提前扣入净值。 |
| 同目标总仓位等权 (`matched_exposure_equal`) | 每个已执行日取该日冻结的 `executed_targets` 之和，同池等权分配，并于该日用相同撮合函数再平衡；每天计入实际代理买卖费用。它匹配的是**目标**总仓位，整手与费用会使实际敞口略有差别。 |

每日记录两条对照及策略的净值、从开户日净收益、最大回撤、交易指令数和费用。`strategy_minus_shadow` 同时给出相对两条对照的差额。同目标总仓位对照帮助观察选股和配置的合计影响；两者的换手和费用路径仍不同，净收益差不能单独归因于选股。固定 80% 对照与策略也未必逐日具有相同实际仓位。

运行：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:scripts python3 scripts/paper_same_budget_evaluator.py \
  reports/quant/paper/random-entry-risk-baseline-v1-runtime2-2026-09-29 \
  reports/quant/paper/ensemble-focus-three-v2-five-bps-runtime2-2026-09-29
```

首日只有同收盘价开仓与估值，上表差值主要对应各自买入金额和费用，**不是价格预测或策略收益的证据**。80% 等权对照尚未清仓，净值没有预扣未来卖出费；若此刻全卖的估计卖出费另列在评估器输出。1/126 的前瞻长度也不足以估计回撤、成功率或跨行情稳定性。

这仍是日收盘价的前瞻**代理**撮合，无法证明盘中成交、涨跌停可交易性、公司行为和分红现金处理正确。时间门槛仅是前瞻可得性的必要条件：账本没有显式的决策生成时间，不能据此证明每条 `pending_decision` 确实在下一次代理成交前已写定。评估器只重放账户已经记录的 session；它不能独立证明交易日历没有缺日，也不能证明记录后的原价数据没有修订。账本原价条没有独立的 `instrument_id` 和 `trade_date` 字段，`payload_hash` 仅能核对格式，无法单凭账本重取原始响应并证明其对应股票、日期；`signal_panel_sha256` 也未从当前数据库重新计算。因此哈希链证明账本内部一致性，不证明外部行情来源真实性。若已记录 session 的原始价条或账本不完整，评估器停止，不插值、不跳过该日，也不发布对照收益。
