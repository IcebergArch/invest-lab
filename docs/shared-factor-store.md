# 分析与量化共用因子观测

分析空间和量化空间读取同一份 `factor-observations-v1` 因子记录，但各自负责不同的判断。**分析**展示某只股票的因子水平、最近变化、价格口径和证据限制，用于解释和发现异常；**量化**在冻结的股票池、决策时点和输入快照上读取完整因子向量，再由一个或多个决策函数、汇聚政策、组合预算与模拟执行确定交易。因子库的登记或数值变化本身都不是买卖指令。

## 存储契约

`factor_store.py` 使用独立的 `data/quant/factors.sqlite3`，以因子 ID/版本/参数、标的、观测日、价格口径、来源和输入快照为身份。每条保存数值或明确缺失状态、单位、输入 SHA-256、来源抓取时间、首次可得时间、证据等级及证据 ID。同一输入身份重算必须得到相同结果；源修订或单位转换算法变化产生新输入哈希和新记录，不覆盖旧值。两端由同一个 `FactorStore` 读取，页面没有写库权限。

| 消费者 | 读取条件 | 输出 |
| --- | --- | --- |
| 分析空间 | 指定股票和截至日期，按相同版本、参数、价格口径、来源及输入快照取最近两次观测 | 水平、变化或明确缺失状态、日期、单位和来源；允许标注为事后归档 |
| 量化空间 | 指定股票池、观测日、因子版本/参数、同一来源快照和价格口径；每只股票每项恰有一个可用值 | 因子向量与输入指纹，供决策函数；缺失、歧义或时间越界时拒绝计算 |

量化读取只接受带证据 ID 的 `verified_first_available`，并要求首次可得时间和来源抓取时间均不晚于决策时点。历史 `daily_bars.fetched_at` 仅代表本地取得时间，不能推断提供方当年首次发布；因此从主库显式物化的值一律标为 `retrospective`，可供分析，**不得作为点时合格的量化输入**。量化规则可通过 `build_daily_rule_proposal_from_store` 消费合格快照；多个函数通过 `combine_daily_rule_proposals_from_store` 汇聚，并经过同一资金预算。它们仍保持 `research_only_unvalidated`，没有接入冻结模拟账户或自动交易。

在仓库根目录手动运行 `PYTHONPATH=src python3 -m quant_lab.cli factor-build --stock stock:603993.SH --sessions 21`，会使用已入库日线生成最近 21 次观测；省略 `--stock` 会处理主库全部股票。物化时沿现有规范化契约把 `lot` 乘 100 转为股数，转换版本写入输入指纹；未知单位或缺失人民币成交额则明确标缺失。运行不联网、不设定时任务。个股报告从同一存储只读显示因子观察；量化空间因子库显示最近来源快照的观测量、缺失量和可得时点证据量。当前 Qlib 归档仍独立于主库，尚无对应的因子物化适配器；其个股报告在没有观测时明确显示空状态。

2026-09-29 的真实主库四只股票已各物化最近 21 个交易日、每股 231 条因子观测。洛阳钼业因子报告可显示 11 个版本/参数组合；另三只的最近成交额缺失，两个成交额相关因子显示 `missing_input`，其余 9 个组合显示数值。首轮未换算 `lot` 的失败观测仍留在旧输入快照中；修正后的观测使用新转换版本和快照，未覆写旧账。

下一阶段须补齐不可变源快照、提供方首次发布时间、复权和成交量单位验证，再为历史决策建立真正点时合格的因子记录。高频 OFI、盘口不平衡和日内实现波动需要逐笔/盘口源，不能从现有日线推算。因子变化检测可由一次明确的数据更新或用户查询触发，是否提醒、提醒阈值和频次由分析侧另定；不直接改变交易决策。
