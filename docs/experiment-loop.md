# 实验目标、记录池与逐例复盘

## 北极星目标

回测优化使用 `return-drawdown-relative-v1`，结果在 **0.0–10.0** 之间并保留一位小数。比较基准为相同股票池、同期、相同统一成本率的等权买入持有；与基准相同为 5.0 分。

```text
收益子分 = 截断到[0,10](5 + 5 × (策略年化收益率 - 基准年化收益率) / 0.20)
回撤子分 = 截断到[0,10](5 + 5 × (策略最大回撤 - 基准最大回撤) / 0.50)
北极星分 = 四舍五入到 1 位(收益子分 × 50% + 回撤子分 × 50%)
```

最大回撤以负数表示，越接近 0 越好；收益差 +20 个百分点或回撤改善 50 个百分点分别对应子分 10.0。两个归一化锚点是**预先固定的政策参数**，不是从这三只股票拟合的。`north_star.py` 在分数旁保存政策版本、原始策略/基准指标、两个子分、权重和锚点。累计收益、年化波动、夏普与换手作为附加原数据一并保存，但在 v1 中权重为 0。以后若加入有效的新加权数据，必须创建 v2、冻结公式，并在同一数据截面与成本下比较，不能悄悄改旧分数。独立前瞻检验、数据质量、可交易性与风控是另设门槛，高分不让它们自动通过。

## 离线参数优化

`quant_lab optimize` 从规范化 `CanonicalDailyBar` 构造同一前复权股票价格面板，输入指纹包含来源、采集批次和价格。每套策略使用固定的三个候选参数组合。历史日期按约 70%/30% 顺序切分；**只在前 70% 按北极星分数选参数**，同分时先选较小回撤，再按预登记网格顺序。后 30% 只检验选中组合，不参与选参。全部候选训练指标、选中参数、基准、留出段指标和输入指纹写入只追加、SHA-256 校验的 `reports/quant/optimizations`。

当前 2026-09-29 的三股试运行：SMA 选 10/40，训练 7.0、历史留出 7.7；横截面动量选 20 日，训练 6.3、留出 7.0；Z 分数均值回归选 40 日/1.5，训练 6.8、留出 4.1。它们依赖事后选定的三股股票池，历史数据也可能修订，所以留出段只是**历史诊断**，`promotion_status=not_eligible`。不得把最高留出分数回头用于这次选参，或把结果称为实时推荐策略。

## 实验记录池与策略库

`strategy_catalog.py` 登记三套可运行实现及因子依赖；`factor_library.py` 登记 SMA、动量、Z 分数的计算定义。实现存在、实验已运行、可投入独立验证是三种不同状态。

每次 `quant_lab research` 或 `quant_lab run` 都向 `reports/quant/strategy-runs` 追加完整回测快照，包含策略/因子版本、参数、股票池、成本、权益曲线、同期基准、时间切分、输入指纹和来源。`run.json` 关联流水线产生的快照 ID。控制台以这些已校验快照构成实验记录池，并展示策略版本当前最近一次结果；单个 `latest/research.json` 仍用于当前报告。输入哈希可发现数据变化，但主库历史仍可被更新，不能代替不可变原始快照。

## 回执、复盘与改版

个股研究报告先存 `research-journal`。用户在量化空间选择一份研究记录，提交一条 `watch / skip / buy / sell` 的人工回执。回执必须关联原报告 ID、日期和内容哈希；决定日期和可选实际成交价、数量及备注存于独立私有文件 `feedback-cases`，控制台列表只展示摘要，页面不会调用券商。

新数据入库后运行 `quant_lab review-cases`：复盘引擎用沪深 300 交易日历核对信号日后的第 5/20/60 个交易日，对主库前复权价计算价格变化并追加 `case-reviews`。若原信号日价格被修订、某个目标交易日该股缺价，或报告来自未核验的 Qlib 口径，结果明确阻断或标记缺失。复盘从**原报告信号日价格**出发，不能推断用户实际买卖收益；成交价和数量保留供日后账户级复核。再次运行同一数据截止日不会重复写同一 case 的复盘。

量化空间有“运行离线参数优化”和“复盘到期回执”按钮，分别触发与上述 CLI 相同的离线实验/复盘入口。API 先保存接收事件并返回任务 ID，结束后把终态写入 `reports/quant/task-runs`；页面按任务 ID 读取状态。当前只有一个本地量化 API 进程执行任务，运行中拒绝第二个任务，服务中断后仅有接收事件的任务显示为“执行中断”，需按成果归档核对。按钮不会同步行情、执行交易或自动修改策略版本。

后续策略改版必须关联受影响的 case、反馈、成熟结果、旧版本与候选新版本，并在相同数据/成本/风控假设下比较，再积累未来独立样本。回执和成熟复盘数量以控制台实时状态为准；未到期 case 保持待复盘。系统不会因一次好看的历史分数自动晋级、改规则或下单。
