# 简版量化数据与验证说明

## 1. 数据渠道

来源按用途分级，避免把 GitHub 仓库误当作原始金融数据：

| 级别 | 来源 | 用途 | 当前是否直接抓取 |
|---|---|---|---|
| T1 | 上海证券交易所 / 中证指数有限公司 | 科创、上证、中证指数代码与编制口径 | 否，作为元数据依据 |
| T1 | 申万宏源研究 | 申万一级行业清单、行业指数日线 | 是 |
| T2 | 东方财富公开行情 | 三只 A 股、五个宽基指数日线首选源 | 是 |
| T2 | 腾讯证券公开行情 | 东方财富连接限流时的日线回退源 | 是 |
| T3 | AKShare（GitHub） | 校验公开接口路径、参数和字段映射 | 否，只作代码参考 |

可核对入口：

- [上证综合指数编制方案（官方）](https://www.sse.com.cn/market/sseindex/indexlist/indexdetails/indexmethods/c1/000001_000001_CN.pdf)
- [沪深 300 指数资料（中证指数官方）](https://oss-ch.csindex.com.cn/static/html/csindex/public/uploads/indices/detail/files/zh_CN/000300factsheet.pdf)
- [申万指数发布页（官方）](https://www.swsresearch.com/institute_sw/allIndex/releasedIndex)
- [AKShare 指数接口文档（GitHub）](https://github.com/akfamily/akshare/blob/main/docs/data/index/index.md)
- [AKShare 申万指数采集实现（GitHub）](https://github.com/akfamily/akshare/blob/main/akshare/index/index_research_sw.py)

代码中的渠道目录是 `quant_lab.data_sources.SOURCE_CATALOG`。每条行情同时保存
`source_id`、`fetched_at`、`payload_hash` 和 `adjustment`，可关联到一次
`sync_runs.run_id`。同步采用主键 upsert，重复执行不会制造重复记录。

实现不依赖第三方 Python 包；HTTP 传输优先调用系统 `curl`（东方财富会间歇性拒绝
本机旧版 Python/LibreSSL 的 TLS 连接），不存在 `curl` 时回退到标准库 `urllib`。

重要边界：东方财富接口免费、免密，但没有面向本项目的可用性 SLA。它适合研究和
原型，不应成为自动交易的唯一行情。当前实现会在其连接被限流时回退到腾讯证券，且
每行保存真实来源，不会把回退数据标成首选源。进入生产前仍应增加持牌行情源并按交易
日做双源对账。前复权价格可能随未来公司行为重算；当前保存抓取哈希，但还不是不可变
快照仓。

## 2. 数据口径

- 股票使用前复权日线（`qfq`），宽基和行业指数使用不复权指数点位。
- 东方财富字段顺序为：日期、开盘、收盘、最高、最低、成交量、成交额等。
- 东方财富成交量保存源端“手”，成交额为人民币元。
- 腾讯证券成交量保存源端“手”，其 K 线返回不含成交额，因此成交额保存为 `NULL`、
  单位标为 `unavailable`。
- 申万接口未在返回体携带量额单位，因此原样保存为 `source_native`；三个策略只使用
  收盘点位，不依赖量额跨源比较。
- SQLite 主键为 `(instrument_id, trade_date, adjustment)`。
- 默认同步截止日为当前自然日的前一天，以免把盘中宽基快照误当作完整日线；可用
  `--end` 显式覆盖。
- 已在主库登记的单只股票可用 `--stock` 定向更新，最多一次 30 只。单独使用时只抓指定
  股票；与 `--group` 合用时合并选择并按标的 ID 去重。例如收盘后更新洛阳钼业：

  ```bash
  PYTHONPATH=src python3 -m quant_lab sync --start 2026-09-29 --end 2026-09-29 --stock stock:603993.SH --workers 1
  ```

  同步进度会逐只显示实际返回的首末交易日。若提供方尚未返回请求末日，该日期不会被
  推算或填充；请以输出日期及库中 `MAX(trade_date)` 核对时效。`sync_runs.groups_json`
  记录显式目标 ID，`daily_bars` 记录实际来源、响应哈希、抓取时间和同一 `run_id`。
- OHLC、正价格、非负量额在写入前和验证阶段各检查一次。
- 不对上游缺失交易日做静默前向填充。当前申万官方历史接口在部分正常交易日存在缺口，
  `verify` 会列出具体日期；策略若使用多个标的，只取共同有价日期。

## 3. 标的覆盖

- 个股：立讯精密、潍柴动力、牧原股份。
- 科创 / 上证：科创50、上证指数。
- 中证：沪深300、中证500、中证1000。
- 行业：申万宏源研究接口在同步时返回的全部一级行业，当前预期为 31 个。代码不使用
  容易过时的手写行业名称表；若返回数量异常或分页不完整，同步会失败而不是静默缺数。

## 4. 三个策略与公式

### 双均线趋势

对每个标的计算 20 日与 60 日简单移动平均。`SMA20 > SMA60` 时进入候选，所有候选
等权；否则持有现金。

### 横截面动量

60 日动量为 `close[t] / close[t-60] - 1`。只保留正动量标的，选择分数最高的一个；
并列时按稳定的标的 ID 排序，确保结果可复现。

### Z-Score 均值回归

使用最近 20 个收盘价的总体标准差，计算
`z = (close[t] - mean20) / std20`。`z <= -1.5` 的标的进入候选并等权；标准差为零时不
产生信号。

## 5. 时序与验证

所有信号只读取截至 `t` 日收盘的数据，在 `t+1` 日收盘代理成交，随后从
`t+1 -> t+2` 的收盘到收盘收益开始生效。日线无法验证 10:30 实际成交。换手按收益后漂移权重与新目标权重的绝对差之和
计算，成本默认是换手的 10 bps；初始建仓也计成本。

`quant-lab verify` 同时执行：

1. 三个公式的手算 oracle；
2. 100 → 110 → 121 → 133.1 的下一收盘成交记账 oracle（期末净值应为 1.21）；
3. 修改未来价格不影响历史结果的泄漏检查；
4. 全库 OHLC、覆盖范围、31 个一级行业及来源血缘检查；
5. 三个策略在三只重点股票真实日线上的完整回测。

报告中的收益只证明代码按上述定义执行，不证明策略有效，也不构成投资建议。
