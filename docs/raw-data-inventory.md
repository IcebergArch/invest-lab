# 原始数据储备盘点

量化系统优先保存**不可从已有数据准确重算的原始观测**，再在因子层生成收益率、均线、波动率、换手率、VWAP 等计算结果。仅有收盘价无法复原实际交易量、成交额、停牌或 ST 状态；成交额也不能由日 OHLC 和成交量精确反推。

## 当前落库结构与真实覆盖

运行下列只读盘点。它不会调用采集接口，也不会修改行情行；唯一写入是原子发布指定的 JSON 报告。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -m quant_lab.raw_data_inventory \
  --main-db data/quant/market.sqlite3 \
  --historical-db data/quant/historical-baostock-raw.sqlite3 \
  --qlib-root data/quant/qlib-releases/2026-09-28/published \
  --qlib-manifest data/quant/qlib-releases/2026-09-28/qlib_bin.manifest.json \
  --qlib-tag 2026-09-28 \
  --out reports/quant/data/raw-data-inventory-2026-09-29.json
```

报告分别列出 `source_id × adjustment × asset_type × volume_unit × amount_unit` 的行情条数、非空成交额、日期范围及来源哈希/Run ID 字段覆盖；历史归档另列 `年份 × 沪/深` 的股票数与行情条数，包括零值年份。当前存储把 OHLC、成交量、成交额、调整方式、来源、响应哈希、采集时间和 Run ID 放在 `daily_bars`；BaoStock 另外把 `tradestatus`、`is_st` 与来源返回的原始人民币成交额放在 `baostock_daily_status`。`fetched_at` 是采集时间，不是市场首次发布时间。

BaoStock 状态行的 `raw_amount_cny` 有 681,960 条非空。其中 **28,546 条**因停牌或 ST 在规范化行情行里把 `amount` 留空，但来源成交额原值仍保留在状态表。模型训练或流动性门槛不能把这类缺失当作零，也不能丢弃原始审计值。上述数字是该次活跃回补库的快照，随后会变化；以报告中的 `generated_at_utc`、Run ID、摘要指纹和年份矩阵对齐讨论。

BaoStock 适配器在不可交易日会把来源空成交量写成 `0`，当前表无法再区分“来源确实为零”和“来源缺失后代填零”。报告因此称 `stored_volume_rows`，并列出 `zero_stored_volume_rows`；后续采集版本应原样保存可空来源成交量，再单独产生规范化数值。

## 下一步原始数据优先级

| 优先级 | 新增或继续归档的来源观测 | 用途与口径要求 |
| --- | --- | --- |
| P0 | 来源前收盘价、未复权 OHLC、原始成交股数、人民币成交额、停牌/ST/交易状态，逐行来源、单位、响应哈希、采集时间和版本。 | 先补全沪深多年与交易所覆盖；前收盘价需保存来源字段，不能只用上一条收盘价代替。现有主库的前复权价与 BaoStock 原价必须保持隔离。 |
| P1 | 分红、送转、配股、拆细等公司行动原始公告；历次总股本/流通股本；原始财报项目及披露时间；历史行业归属和生效/发布时间。 | 用于总回报和实际可交易股票池的点时点重建。换手率需要当时流通股本，不能仅由交易量算出。 |
| P2 | 两融余额和买卖额、按规则版本保存的北向资金汇总、基金/ETF 份额和申赎等可核验资金观测；需要时再考虑逐笔或盘口。 | “资金流”不能由量价准确反推。任何供应商的资金流估计须保存算法/口径，不可伪装为交易所原始买卖明细。北向口径随制度变化需保留时间段规则。 |

`returns`、均线、动量、波动率、技术指标、VWAP、换手率和策略信号进入可重算因子库，记录输入版本、参数、生成代码版本与计算时间。`factor`、`adjclose` 等来源提供的变换值可保留用于对照，但不能代替公司行动原始事件。

## 快照、完整性与限制

主库和 BaoStock 库使用 SQLite 同一只读事务；事务开始后执行 `PRAGMA quick_check`，失败即把该源标记为不可用。活跃 WAL 库缺少 sidecar 时，SQLite 的 `mode=ro` 可能无法打开。此时盘点仿照已有 `archive_status` 使用 `mode=rw` 连接、立即设置 `PRAGMA query_only=ON`，只执行只读 SQL；SQLite 可能创建 `-wal`/`-shm` sidecar，报告会明确标出。它不使用 `immutable=1`，因为那可能漏掉活跃 WAL 数据。报告的 `summary_sha256` 只绑定本次聚合摘要，不是整库字节哈希；DB 与 WAL 的前后大小和修改时间可显示运行期间是否变化，但不破坏已建立事务的一致视图。

Qlib 盘点核对固定 manifest、发布索引以及实际日历和股票列表文件哈希，只读约 8 MB 索引和两个小文本文件，不扫描 6 万多个特征二进制。发布索引保留每个文件的哈希，但本次盘点未逐一复核特征文件内容或有效值。Qlib 的单股读取和较大范围交叉对账见[Qlib 归档说明](qlib-archive.md)。所有目前保存的历史值仍缺全量“当时首次公开时间”与不可变历史版本，不能仅凭本盘点宣称点时点回测就绪。
